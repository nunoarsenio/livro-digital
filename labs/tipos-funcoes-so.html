Os pedidos que os programas fazem ao SO

Os programas pedem serviços ao SO através de chamadas ao sistema (system calls). Há centenas, mas dividem-se em seis tipos. Escolhe uma ação e vê, uma a uma, as chamadas que o programa faz, como se usasses o Process Monitor no Windows ou o strace no Linux.

    O que está a acontecer

    • Carrega em Reproduzir ou em Seguinte.

    Os seis tipos

    • Controlo de processos: criar, terminar, esperar, pedir memória.
    • Gestão de ficheiros: criar, abrir, ler, escrever, fechar.
    • Gestão de dispositivos: pedir, usar e configurar dispositivos.
    • Informação: obter a hora, o identificador do processo, dados do sistema.
    • Comunicações: trocar dados com outros processos ou computadores.
    • Proteção: consultar e alterar permissões.

    No Windows, os programas usam a API Win32, que por sua vez faz as chamadas ao núcleo do Windows (NT). O Process Monitor, da Microsoft (Sysinternals), mostra-as em tempo real.

    As ferramentas que vêm com o SO

    Além do núcleo, o SO traz programas utilitários que ajudam a gerir o computador. Cada um está ligado a uma função do SO. Descobre qual.

    Onde os encontrar no Windows

    • Muitos abrem-se pela janela Executar (Win+R), escrevendo o nome curto: taskmgr, devmgmt.msc, eventvwr, resmon, cleanmgr, services.msc (serviços), diskmgmt.msc (gestão de discos), msinfo32 (informações do sistema).
    • Também estão no menu que aparece com o botão direito no botão Iniciar (ou Win+X).
    • O Painel de Controlo e as Definições reúnem quase todos.
    • No Linux há equivalentes: top, lsblk, journalctl, o Monitor do Sistema…

    Na linha de comandos do Windows

    • tasklist / taskkill: processos.
    • systeminfo: informação do sistema.
    • driverquery: controladores instalados.
    • chkdsk: verificar o disco.
    • sfc /scannow: verificar e reparar ficheiros do Windows.
    • wevtutil qe System /c:5: últimos eventos do sistema.

    O SO toma nota de tudo

    Uma função importante do SO é detetar erros e registar o que acontece. No Windows, os registos veem-se no Visualizador de Eventos (eventvwr); no Linux, com journalctl. Os técnicos de informática usam-nos para descobrir a causa dos problemas. Acompanha um dia de registos.

    O que está a acontecer

    • Carrega em Reproduzir ou em Seguinte.

    Os níveis

    • Informação: tudo correu bem (um serviço arrancou, uma atualização foi instalada).
    • Aviso: ainda não é um problema, mas pode vir a ser.
    • Erro: algo falhou.
    • Crítico: falha grave, como um encerramento inesperado.

    O SO não se limita a registar: muitas vezes reage sozinho, reiniciando um serviço, avisando o utilizador ou mudando para outro dispositivo.

    No Windows

    • Abre-se com Win+R → eventvwr.
    • Os eventos estão em vários registos: Sistema (o próprio Windows e os controladores), Aplicação (os programas) e Segurança (inícios de sessão, acessos).
    • Cada evento tem um ID. Alguns que os técnicos conhecem de cor: 41 (Kernel-Power: o PC desligou-se sem encerrar), 6008 (encerramento inesperado), 7 e 153 (problemas no disco), 1000 (um programa falhou), 4625 (palavra-passe errada).
    • Na linha de comandos: Get-WinEvent -LogName System -MaxEvents 20 (PowerShell).

    Para quem trabalha cada função?

    As funções do SO dividem-se em dois grupos: as que ajudam o utilizador (tornam o computador fácil de usar) e as que servem para gerir o sistema (para que funcione de forma eficiente e segura, sobretudo quando há muitos utilizadores e programas). Classifica cada uma.

    Duas perspetivas

    • Do ponto de vista do utilizador, o SO deve ser cómodo e fácil: interface, executar programas, ler e gravar ficheiros, comunicar, avisar dos erros.
    • Do ponto de vista do sistema, o SO é um gestor de recursos: reparte o processador, a memória e os dispositivos, regista quem usa o quê e protege tudo e todos.
